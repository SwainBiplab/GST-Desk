# Threat model

Last refreshed at the close of Phase 1. Update it when a phase adds an asset, an entry point or a trust boundary (the next ones are the LAN server, sync, the API, portals and the AI gateway).

## What is being protected

| Asset                                               | Where it lives                                                                                                                                                         | Why it matters                                   |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Business books: documents, parties, items, payments | A SQLite file on the user's device (OPFS in a browser, the data folder on the desktop)                                                                                 | Money, GSTINs, customer identities; a tax record |
| Backups and exports                                 | `.gstbk` ZIPs, JSON and CSV exports, a folder the person chooses                                                                                                       | A copy of everything; handed to others sometimes |
| Update channel                                      | `latest.json` and installers from the release host                                                                                                                     | A bad update runs code on every install          |
| Cloud-drive credentials (desktop, opt-in)           | Secret settings on the device                                                                                                                                          | Access to the person's own drive                 |
| The release signing key                             | Held by the release owner (`docs/runbooks/signing.md`)                                                                                                                 | Whoever has it can ship code to every install    |
| GSP credentials (e-invoice and e-way bill, Phase 2) | Encrypted on the device with a key derived from a PIN the person chooses (PBKDF2, AES-GCM); never logged, redacted in the audit trail; left out of backups and exports |
| Paired tablet tokens (LAN, Phase 2)                 | Only their SHA-256 hashes in the `devices` table; the token itself lives on the tablet                                                                                 |
| Offline model files (Phase 2)                       | `<data>/models` on the desktop, the private file system in the browser; public, licensed files, checked by hash                                                        |
| Usage counters (opt-in)                             | `localStorage`, optionally sent weekly                                                                                                                                 | Privacy: must never carry content                |

## Trust boundaries and entry points (Phase 1)

| Entry point                                                           | Who controls the input                                                       | Defence                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The UI: forms, grid cells, command bar                                | The person using the app                                                     | Validation in the domain package; every query is parameterised through Drizzle; text is rendered by React (escaped)                                                                                                                                                                                                                                                                                                                                                               |
| Rich text in notes and terms                                          | The person, or text pasted from anywhere                                     | Allowlist sanitiser (`richtext.ts`) on write and read; paste is taken as plain text; the only `innerHTML` assignment is the sanitiser's output                                                                                                                                                                                                                                                                                                                                    |
| Files: CSV import, JSON import, `.gstbk`, images, supplier bills      | Anyone who sends the person a file                                           | File type by magic bytes, size limits (25 MB import, 10 MB attachment), manifests and checksums verified, `sanitizeIncoming` drops secret settings and scrubs the audit trail on every way in                                                                                                                                                                                                                                                                                     |
| A `.gstbk` opened from the file manager (desktop)                     | Anyone who sends the person a file                                           | Only `.gstbk` can be read by that command; it opens the restore dialog, which shows what the file holds and asks first                                                                                                                                                                                                                                                                                                                                                            |
| `gstdesk://` links (desktop)                                          | Any web page or email                                                        | An allowlist of pages (inbox, dashboard, reports, a new bill, backup settings); nothing carries data or acts                                                                                                                                                                                                                                                                                                                                                                      |
| The Rust IPC commands (desktop)                                       | The page's JavaScript                                                        | Minimal capability file; commands validate their input (restore folders by name pattern, backups by extension, move target must be empty and outside the old folder); a release build ignores test hooks                                                                                                                                                                                                                                                                          |
| The update channel                                                    | Whoever controls the release host or the network                             | Minisign signature verified against the public key compiled into the app; a tampered download is refused (tested with a tampered fixture)                                                                                                                                                                                                                                                                                                                                         |
| Another site loading the app in a frame, or injecting script          | The web                                                                      | A Content-Security-Policy (meta tag, and as a header with `frame-ancestors none` by `public/_headers`); no third-party scripts; `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`                                                                                                                                                                                                                                                                                 |
| The usage-counter endpoint (if a build sets one)                      | The operator                                                                 | Opt-in, off by default; a fixed allowlist of feature names and counts; no cookies, no referrer; the exact payload is shown in Settings                                                                                                                                                                                                                                                                                                                                            |
| The GSP connection (e-invoice, e-way bill; Phase 2)                   | The GSP vendor and whoever sits on the network                               | TLS to a configured base URL only; credentials decrypted with the PIN for the session and never written; every request and response redacted (`packages/gsp/src/redact.ts`) before the audit log; the portal's answers are validated before an IRN or EWB is stored; a sandbox is a separate setting                                                                                                                                                                              |
| Tally XML, Vyapar and Excel files (Phase 2)                           | Anyone who sends the person a file                                           | A streaming XML reader that builds no full tree and keeps a size budget; spreadsheets read cell by cell with strict numbers; every row is planned (dry run) and shown before anything is written; imported documents are rebuilt by the engine, never copied                                                                                                                                                                                                                      |
| The LAN server (desktop, only when switched on)                       | Anyone on the same network, including guests and other shops on shared Wi-Fi | Off until switched on; TLS; a one-time 8-digit code for 5 minutes, 5 wrong tries burn it and the address waits 60 s; per-device tokens stored only as hashes, rotated at 30 days, revoked at once; roles checked per method against a whitelist (no queries, exports or settings); request-size limit, rate limits and a reply timeout; static files served with a path-traversal guard                                                                                           |
| The model manifest and model files (Settings, AI)                     | Whoever controls the manifest host or the network                            | The manifest is Ed25519-signed with a key compiled into the app and refused otherwise; only https or localhost; every file is checked against its SHA-256 before it is called ready; nothing is downloaded before the person accepts the licence; the sidecar servers bind to localhost and are child processes stopped with the app; a runtime zip is unpacked with path checks                                                                                                  |
| A scanned bill (image, PDF)                                           | Anyone who sends the person a bill                                           | Type by magic bytes, 10 MB limit, rasterised in the page; OCR text is data: the model's answer is grammar-constrained and schema-validated, matched to the books by id, and nothing is written until a person accepts                                                                                                                                                                                                                                                             |
| The cloud API (`apps/api`, Phase 3)                                   | Anyone on the internet                                                       | TLS at the proxy; every route a Zod contract; sessions by better-auth (one-time codes, 5 attempts, origin check for cookies, bearer for apps); the request's organisation from the path checked against membership; every query as the `gst_app` role under row-level security with `app.org_id` on the transaction; per-address and per-organisation limits; 2 MB bodies; the error envelope never carries internals; secrets only from the environment and refused when default |
| Object storage (signed URLs)                                          | The client that holds a URL                                                  | Ten-minute signed PUT and GET; keys made on the server under the organisation; type and size checked before signing; server-side encryption; the API never proxies bytes                                                                                                                                                                                                                                                                                                          |
| Sync (`/v1/sync/*` and the PowerSync service)                         | A signed-in member's device, or anyone holding its token                     | Device tokens are signed by the API only after a membership check and carry the organisation the sync rules filter on; uploads go through the same session, membership, role and RLS checks as every route, apply whole or not at all, are recorded so a retry is applied once, and every document issued or revised is priced again by the engine; issued money changes only by revision; secret settings never upload; a refused change is sent back so the device converges    |
| Team and permissions (`/v1/orgs/:id/team`, invites, roles, approvals) | A member trying to do more than their role                                   | One shared matrix checked per request and per sync transaction; only owners touch owners; nobody grants more than they hold; the last owner stays; better-auth's organisation endpoints are closed; invitations match the signed-in e-mail or phone and are not found by anyone else; approvals are applied as the requester with their role checked again, never self-approved                                                                                                   |
| Local storage and the data folder                                     | Other software on the same machine, other users of the computer              | Not defended against a person with the user's own account: the data is not encrypted at rest (see residual risk)                                                                                                                                                                                                                                                                                                                                                                  |

## Threats considered and what answers them

- **A crafted backup or import plants a setting that sends data elsewhere** (found by the automated review in prompt 20): secret settings are dropped on every inbound path and again just before the write; hostile-file tests exist.
- **A malicious `.gstbk` overwrites the books**: restore builds the new database beside the live one, checks it, and swaps only after; the old one is kept for a week with an automatic way back; a restore asks first and makes a backup of what is there.
- **A link or file opened from outside does something without asking**: neither can change data on its own.
- **Update substitution**: signature verification; the public key is in the binary; the previous version is kept.
- **Telemetry becomes surveillance**: the list of countable things is a code allowlist, unknown names are dropped, turning it off deletes what was waiting, and a test asserts the payload holds no content.
- **Logs leak customer data**: diagnostics scrub emails, GSTINs, PANs, ids, long numbers and user names; they never include the database.
- **Supply chain**: lockfile with frozen installs in CI; Dependabot; workflow permissions are read-only except the release jobs; `pnpm audit` and `cargo audit` are in the Phase 1 review.

- **Someone on the Wi-Fi tries to pair or guess a token**: codes are random, single-use and short-lived with a burn after five misses; tokens are 256-bit random; limits apply per address and per device; a wrong token and a missing token look the same.
- **An impostor answers at the shop's address (or `gstdesk.local`)**: the person is asked to compare a fingerprint on first use and the QR carries it; the impostor would still need the code shown only on the real desktop. Residual risk: a person who clicks through the warning without checking. Not defended: an attacker who is already on the computer.
- **A stolen or lost tablet**: remove it in Settings; its token stops working at once.
- **A modified tablet app asks for more than its role**: the role is enforced on the desktop, by method.
- **Two devices change one document**: edit locks; the loser is told who has it.

- **A model is told to do something by the text on a bill** (prompt injection): the model can only answer in the schema's shape, the answer is validated, and the result is a review card a person accepts; it has no tools and no way to act.
- **A hostile manifest points at a huge or malicious file**: signature first; size shown and licence accepted before anything is fetched; hash checked after; a server that ignores a range restarts the download rather than appending.

- **A vendor's GSP answer carries something hostile**: responses are parsed into typed records, the IRN and signed QR are stored as data, nothing from the portal is rendered as HTML.
- **A crafted Tally file or spreadsheet**: no XML entities are expanded (the reader is ours), file size is bounded, numbers are strict, and the plan is shown before the write; a hostile file can at worst produce a plan the person declines.

- **A member of one organisation reads another's rows through the API**: the policy is enforced by Postgres on the app role, not by the code; the matrix test proves zero rows across every table and that a write under the wrong organisation changes nothing.
- **A stolen bearer token**: sessions expire in 30 days and are revocable (`/v1/auth/sign-out`, and the session table); the token is scoped to the API's origin in the client. The desktop keychain is B-163.

- **A device edits money it should not** (a changed total, a changed issued invoice): the engine re-prices every document issued or revised in an upload; an issued document's money changes only through a revision; a refusal is recorded and the server's version goes back down.
- **The download stream leaks another organisation's rows**: logical replication bypasses RLS, so the sync rules filter by the organisation in a token only the API signs, after checking membership. Residual risk: a leaked `POWERSYNC_JWT_SECRET` lets anyone mint tokens; keep it in the secret store and rotate it with the service.

- **Privilege escalation inside an organisation**: an admin promoting someone to owner, a team lead inventing a wider role, or calling better-auth's own organisation endpoints. Refused by `canManage` and `grantsWithin`, and the endpoints answer 404; tested route by route and role by role (`apps/api/test/team.test.ts`).
- **A removed member keeps reading**: API calls and uploads stop at once; PowerSync downloads stop when the 5-minute token lapses (B-175).

## Out of scope for Phase 1 (to be added with the phases that introduce them)

Sync and its authorisation (prompt 41), the cloud API and Postgres row-level security in production use, customer portals, the cloud AI gateway (prompt 48).
