# Security review: Phase 1

Procedure: `prompts/cross-cutting/90-security-review.md`. Scope: everything shipped in Phase 1, the web app, the database and backup code, the desktop shell (prompt 23), the review inbox rules, the localisation tooling and the usage counters. The threat model is `threat-model.md` (refreshed with this review).

## Result

**No open Must findings.** Three Must findings were found and fixed during the review (below). Automated scans are clean of high and critical issues, except where a tool was not run, which is listed plainly.

## Findings

| #   | Severity | Finding                                                                                                                                                                                                                                                                                            | Status                                                                                                                                                                         |
| --- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Must     | The web app had no Content-Security-Policy and sent no framing or sniffing protection.                                                                                                                                                                                                             | Fixed: a CSP meta tag in `index.html`; `public/_headers` sends the same policy plus `frame-ancestors none`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. |
| 2   | Must     | `cargo audit`: the `zip` crate 2.6.1 had four advisories (one critical, three high), all in `ZipArchive::extract`. We only write ZIPs (diagnostics) and never extract, so the paths were not reachable, but the dependency was flagged.                                                            | Fixed: upgraded to `zip` 9; the audit reports no vulnerabilities.                                                                                                              |
| 3   | Must     | Accessibility defects on every route (also a release gate): controls whose accessible name did not contain their visible text, an unnamed rich-text box, preview pages with no alternative text, focusable content inside a hidden region, a card list that nested buttons inside listbox options. | Fixed; see `docs/qa/a11y.md`.                                                                                                                                                  |
| 4   | Should   | Data is not encrypted at rest (the SQLite file and OPFS are readable by anyone with the user's own account or disk).                                                                                                                                                                               | Backlog B-087 (Phase 4, with the key-management work). | 5   | Should   | `style-src 'unsafe-inline'` is needed by the UI library's inline styles.                                                                                                                                                                                                                           | Backlog B-088: move to nonces or hashed styles when the UI kit allows it.                                                                                                      |

## Residual risk

The device is trusted: anyone who can read the user's files can read the books (finding 4). The release key is a single point of trust for updates (the release owner holds it; rotate as in `signing.md`). Hosting headers (`_headers`) only apply where the host honours that file.
