# 0008 — Printing: templates, PDFs, thermal receipts and sharing

Status: accepted. Context: prompt 17, PRD FR-060 to FR-065, FR-150, UX-09, CR-01, NFR-10.

## Decision

- **One layout engine, two renderers.** `@gst/print` lays a document out as positioned boxes (text, rules, rectangles, QR, images, in points). The editor's live preview and the designer draw those boxes as SVG; the PDF writer draws the same boxes with `pdf-lib`. They cannot disagree because there is only one layout. The prompt asked for react-pdf components and a snapshot test comparing preview and PDF boxes; react-pdf has its own layout engine (yoga), so an HTML preview could only ever approximate it. Owning the layout makes "what you see is what prints" true by construction, keeps the output deterministic and small, runs unchanged in a Web Worker and in Node, and lets the same library stamp CANCELLED onto an existing PDF. The cost is that we own text wrapping and pagination, which the tests below cover.
- **A template is JSON** (`TemplateSpec`, validated with zod on import and on load): page size and margins, theme colours, text sizes, style (title band, table lines, zebra, header layout), blocks with their order and visibility, columns with widths, tax column mode, copies, watermark, label overrides, and a thermal variant. The five presets (Classic, Modern, Compact, Tally-like, Retail) are ordinary specs; nothing is special-cased in layout. Saved templates live in `templates.config_json`; the default per document type and per shell is the `print.defaults` setting, and a missing or deleted default falls back to Classic rather than failing a print.
- **Blocks sit in zones and the designer reorders within a zone.** Top (business, title, party), the lines table, the closing group, and the page footer. This is what lets pagination keep its rules whatever the user designs.
- **Pagination.** A table row is never split. The closing group (tax summary, totals, bank, terms, signature) is measured as one unit and moves whole to the next page when it does not fit; if it is taller than a page even alone, each block moves whole. Later pages carry a "continued" strip and the repeated table header; every page says "Page x of y". Tested at 1, 25, 60 and 200 lines, and for every preset on A4, A5 and Letter.
- **Rule 48 copies** are three labelled passes of the same layout (Original for Recipient, Duplicate for Transporter, Triplicate for Supplier), a template setting.
- **Fonts and scripts.** Noto Sans for Latin and the rupee sign, plus Noto Sans for Devanagari, Tamil, Bengali and Gujarati. Text is split into runs by script, each drawn in its own family; the document's names and addresses can be in any script whatever the template language is. Fonts are embedded as subsets and the text stays real text (checked by extracting it from the generated PDF). Font files are separate assets fetched the first time a script is needed and cached by the service worker, so printing works offline after the first print.
- **Measuring.** Latin runs use cached per-glyph advances (fast); Indic runs are shaped with fontkit. Layout of 200 lines takes about 10 ms warm, so the preview follows an edit within the 300 ms budget (150 ms debounce plus layout).
- **Issued documents print from what was stored, never from a recalculation.** `buildStoredPrintModel` reads the document and line rows; the editor's live preview prices the draft with the engine (`buildPrintModel`). A test checks that for a document made in the app the two give the same totals, lines and tax summary. A recalculation could differ from what was issued after a rate or rule changed, and a seeded document without editor settings would have printed the wrong tax heads.
- **PDF generation runs in a Web Worker.** Fonts are sent once per worker; each request carries only the document, so a long invoice or a bulk export never freezes the page. A cancelled bulk export ends the worker. PDFs are deterministic (fixed dates, no object streams), so saving a document twice gives the same bytes and the same file name (`<Business>_<FY>_<Type>_<Number>.pdf`).
- **The PDF is kept with the document** as an attachment, replacing any earlier file of the same name. When a document is cancelled, a saved PDF gets CANCELLED stamped across every page (the original text stays underneath and selectable) and replaces the saved file; new renders carry the watermark from the layout. DRAFT and CANCELLED watermarks are automatic, and a template can add its own word.
- **Print** is `window.print()` of the SVG preview with a print stylesheet that shows only the sheet, one page per sheet; the app around it is never printed. (Before this there was no print stylesheet, so printing printed the whole screen.)
- **Thermal receipts.** One composer turns the print model into lines that fit the roll (32 characters at 58 mm, 48 at 80 mm). The lines become ESC/POS bytes (initialise, alignment, bold, double size, codepage 437, native QR, raster images, partial cut, optional cash-drawer kick) or monospaced text for the browser's print dialog at the chosen width, so the two look the same. A thermal printer has no Indian-script fonts, so a Hindi, Tamil, Bengali, Gujarati or Marathi line goes as a bitmap the caller draws; without one the receipt prints in English rather than as question marks. The rupee sign prints as "Rs".
- **Sharing.** Where the device has a share sheet that takes files, the PDF goes through it. Otherwise WhatsApp opens with the message ready and the PDF is saved so it can be attached: a web page cannot attach a file to a WhatsApp chat. Email does the same with `mailto:`. The message text is a per-language template. A client-portal link is a disabled placeholder until Phase 3.
- **Bulk export** makes each PDF in the worker, one after another, with progress and cancel, and downloads one ZIP (PDFs stored, not recompressed). File names come from a pattern setting (`{type}-{number}` by default; `{party}`, `{date}`, `{fy}`, `{business}` too), made unique within the ZIP.

## Consequences

- Printed text for Indic scripts relies on the font's advance widths and fontkit's glyph substitution; mark positioning from GPOS anchors is not applied by `pdf-lib`. The shapes are right, but small diacritic offsets should be checked by eye on a printout (`docs/qa/pdf-matrix.md`).
- The printed notes and terms are plain lines (bullets for lists); bold and other formatting are kept in the editor and the stored text but not on the page yet (backlog B-034).
- The amount in words is Indian-grouped English or Hindi; Tamil, Bengali and Gujarati print the English words and Marathi the Hindi words until their own are written.
- The label translations are first drafts and need review by native speakers (`docs/qa/print-language-review.md`).
- Saving a PDF to a folder like `Documents/GST Desk/<Business>/<FY>/<Type>/`, and printing straight to a USB or network thermal printer, need the desktop app's native side (Tauri) and are not in this change; the browser keeps the PDF as an attachment and downloads it (backlog B-032, B-033).
