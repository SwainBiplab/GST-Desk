# v0.1.0-beta.1

**Status: not released.** This is the record for the first beta. The release is built as a **draft** by `desktop.yml` and stays a draft until a person publishes it; nothing was tagged, built by CI or published in preparing this page. The version number, tag and installers are produced by the release workflow from the changesets (`docs/runbooks/release.md`).

## What this beta is

The Phase 1 product: billing and books for a small Indian business, on your own computer. Parties, items with an HSN master, invoices and the other document types with GST worked out by an engine, numbering and cancellation with an audit trail, payments and receipts, PDF and thermal printing with templates, reports and dashboards, basic inventory, backup, restore, export and import, a review inbox of things the app noticed, six-language print labels and a translated interface (Hindi complete), typing names in Indian scripts, in-app help, a desktop app with an installer and updater, and opt-in anonymous usage counters.

## Release notes (drafts for review)

Short user-facing notes in the six languages. English is written by the team; the others are first drafts waiting for a native speaker (see `docs/i18n/review.md`).

**English**

- Make a bill, issue it, record the payment, and see what customers owe: all on your own computer.
- The inbox tells you about possible duplicates, missing HSN codes, overdue customers, low stock and old drafts. Nothing changes until you accept it.
- Hindi is fully translated; Marathi, Tamil, Bengali and Gujarati are partly translated.
- Type names in Hindi, Tamil, Bengali or Gujarati letters by typing them in English letters.
- Press F1 for help on any screen. Backups: make one now (Settings, Backup).
- Beta: installers are not signed yet, so your computer may warn you. Please report problems from Settings, Desktop.

## Rollback plan

- **Before publishing:** delete the draft release. Nothing has reached anyone.
- **After publishing, a bad build:** point `latest.json` back at the previous release (keep every release's `latest.json`), mark the bad release as a pre-release, and ship a hotfix with a higher version (never reuse a number). Steps are in `docs/runbooks/release.md`, "Roll back".
- **On a person's computer:** the desktop app keeps the version it was running in `previous/<version>/` inside the data folder (the last two), and takes a backup before it migrates a database that holds data. If an update goes wrong, install the previous version and, only if data was lost, restore the pre-migration backup (Settings, Backup).
- **Data:** migrations only move forward. A release that changes the schema must say so here and carry a forward repair if it has to be undone.
