# Accessibility

## Automated audit (axe)

`apps/web/e2e/a11y.spec.ts` loads the demo business and runs axe-core (rules for WCAG 2.0 and 2.1 levels A and AA) on every route, in both shells, in the light and the dark theme: 9 routes in Shop, 18 in Books (every navigation page, the invoice editor, a report, and eight Settings tabs). A serious or critical violation fails the test. CI archives each run's full report (`apps/web/a11y-reports/<shell>-<theme>.json`, including the minor ones).

Latest run (1366 by 768, compact density in Books): **4 of 4 passing, no serious or critical violations on any route.**

### What the first run found, and what was done

| Rule                                    | Where                                                                                                                                                                                                             | Fix                                                                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `label-content-name-mismatch` (serious) | Business switcher, density button, Shop's navigation links with counts, the notification bell, the invoice totals buttons: the accessible name did not contain the text a person sees on the control (WCAG 2.5.3) | The name now starts with what is shown: `Demo Traders, Business`, `Compact, Density`, `Parties 50`, `3, Notifications: …`, `₹1,180.00, Explain Total`. |
| `aria-input-field-name` (serious)       | The notes and terms boxes in the editor                                                                                                                                                                           | The box is named by its visible label (`aria-labelledby`).                                                                                             |
| `svg-img-alt` (serious)                 | The print preview pages (editor and the print designer)                                                                                                                                                           | Each page says which page it is: "Page 1 of 2 of the document preview" (translated).                                                                   |
| `aria-hidden-focus` (serious)           | Shop's Sell screen: the preview kept off screen for printing                                                                                                                                                      | The region is `inert`, so it is neither read nor reachable by keyboard.                                                                                |
| `nested-interactive` (serious)          | The inbox in Shop: cards with buttons inside a list of options                                                                                                                                                    | In Shop the list is a plain list of items (the cards hold buttons); Books keeps the listbox.                                                           |

## Keyboard

What is checked automatically (the end-to-end suite uses no mouse for these):

- `Ctrl+K` and `/` open the command bar; Up, Down, Enter run an action; `Esc` closes it and focus goes back to where it was.
- `?` opens the keyboard map and `F1` opens help for the current screen; `Esc` closes both and focus returns.
- Books: `G` then a letter goes to each page; `N` opens the new-document menu.
- Inbox: `J`, `K`, `A`, `E`, `R`, `S`, `O`; 20 items are cleared by pressing `A` in well under two minutes.
- The invoice grid: arrow keys, `Tab`, `Enter` on an item opens the picker, rows can be pasted.
- Dialogs come from Radix, which traps focus and closes on `Esc`; the keyboard map, help, bulk accept, reject and restore dialogs are exercised in the suite. Not every dialog has its own test.
- Transliteration field: Up and Down choose a spelling, `Space` or `Enter` takes it, `Esc` keeps the letters.

## Not done yet

- **A recorded keyboard-only walkthrough by a person** (and with a screen reader: NVDA on Windows, VoiceOver on macOS) has **not** been done. The checks above are scripted, which finds missing names, traps and unreachable controls but cannot judge whether a screen reader's reading order and wording make sense. This is the main gap in the Phase 1 accessibility record; it is B-091 and should be done with someone who uses a screen reader daily.
- Axe cannot judge everything: contrast of text over images, meaning of colour, reading level. A manual pass of both themes at 200% zoom and with reduced motion is part of the beta checklist.
- The audit runs at one viewport (1366 by 768). Narrow (phone) layouts arrive with the mobile app (prompt 43).
